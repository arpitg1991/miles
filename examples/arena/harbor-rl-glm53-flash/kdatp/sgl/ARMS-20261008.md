# Engine speed-up arms, 2026-10-08 — bench, live A/B, then the final-v10 launch

Hand-off for the agent that launches `acuadron-agentic-debt-final-v10`. Context: `training-runs/studies/agentic-debt-v9-sample-length-growth/STUDY.md` (why the recipe changes) and `training-runs/harbor-rl-glm53-flash/acuadron-agentic-debt-r3par-ab/RECORD.md` (r24, the parallel routing loads).

## Why

final-v9's 48 engines average 1,300 output tok/s each (4.5M tok/h) against 2,450 tok/s while they decode: half of the engine time is prefill and scheduling, and the decode step is about 30 ms at batch 28 on the plain TP8 + EP8 all-reduce path (`enable_dp_attention=False`, `moe_a2a_backend=none`, no two-batch overlap). Throughput plateaus above ~24 running requests, so concurrency per engine buys nothing. The levers left after `combo-nextn3` (engine-ab-v1) are the serving layout, the speculation depth, the KV dtype and the KV pool. Target: 64 usable groups per ~11 min on 16 + 48 nodes at batch 512 (a 13-min step), which needs about 2x the usable groups per engine-hour.

Already active, do not re-test: the allreduce fusion. `sglang_enable_flashinfer_allreduce_fusion: true` becomes `flashinfer_allreduce_fusion_backend='auto'` in this SGLang (the boolean prints `False` in the server args by design).

## Step 1 — one-node bench (2 jobs in parallel, ~2.5 h)

`sgl_bench.py` has the arms (`live` = final-v9's engines; a later flag overrides an earlier one):

| arm | adds to `live` | expected |
|---|---|---|
| `live-dpa` | `--enable-dp-attention --dp-size 8 --moe-a2a-backend deepep --enable-two-batch-overlap` | 1.5-2x decode; the big one. Risk: the KDA layers under DP attention; the image has `sgl-deep-ep 0.1.0` and `nvidia-nvshmem-cu13`. |
| `live-spec4-5`, `live-spec5-6` | 4 / 5 draft steps, 5 / 6 draft tokens | accept length 2.6 -> ~3.3 of 6: +15-25% |
| `live-spec4-topk2-8` | 4 steps, top-k 2, 8 draft tokens (a tree) | maybe more; costs verify compute |
| `live-fp8kv` | `--kv-cache-dtype fp8_e4m3` | +5-10%, more KV room |
| `live-mem85` | `--mem-fraction-static 0.85` | fewer prefix evictions |
| `live-fp8w` | `--quantization fp8` (dynamic, bf16 checkpoint) | +30-50% at small batch; **numerics risk**, see the gate below |
| `live-dpa-spec5-6`, `live-dpa-spec5-6-fp8kv` | combinations | |

```bash
  aws --profile arena-prod-bom-user s3 cp sgl-run.sh ${H}sgl-run.sh
  sed -e "s#__IMAGE__#$IMAGE#" -e "s#__STAMP__#$STAMP#g" -e "s#__ARMS__#$ARMS#" sgl-job.yaml | $K create -f -

# results: s3://arena-scratch-prod-bom-ap-south-1/acuadron/kdatp/sgl/<STAMP>/SUMMARY.md ; delete the jobs by hand
```

Read, per arm: `real c45 out tok/s` and `TPOT` (the live load is 24-31 running requests, so c45 is the closest column), `real accept len`, the greedy routing-capture check (160 rows for 160 tokens, ids in range, dense layers zero) and the greedy log-prob delta against `live` (run-to-run noise is 0.015-0.06 mean |delta|; `live-fp8w` above that band is the expected outcome and the live gap decides).

Pick the fastest arm whose routing capture passes. Record the table in `README.md` as the earlier jobs did.

## Step 2 — live A/B at 16 nodes (~2.5 h, the gate for the launch)

Base: `training-runs/harbor-rl-glm53-flash/acuadron-agentic-debt-r3par-ab/workflow.yaml` (8 actor + 8 engines, r24, batch 256, final-v9's dataset). Put the winning flags into its `miles-config` as `sglang_*` keys (edit the existing `sglang_speculative_num_steps`, `sglang_speculative_num_draft_tokens`, `sglang_kv_cache_dtype`, `sglang_mem_fraction_static` in place; add `sglang_enable_dp_attention: true`, `sglang_dp_size: 8`, `sglang_moe_a2a_backend: deepep`, `sglang_enable_two_batch_overlap: true` only if the arm has them), new `experiment-name` `acuadron-agentic-debt-engine-ab-v3`, submit, run 2 steps, stop.

Pass criteria (`trainer-worker-0` log and W&B):
- engines serve and the weight push fills them (dummy load): `Timer update_weights end` about 30 s, no engine restart;
- `train/train_rollout_logprob_abs_diff` at steps 0 and 1 at most 0.045 (r3par-ab: 0.033 / 0.036; a wrong engine numerics shows as 0.1+). For `live-fp8w` also `train/tis_clipfrac` under 0.005;
- `accept len` in the `Decode batch` lines above the live 2.6 for a speculation arm;
- `Routing replay: materialized expert blobs for 32 groups ... dropped 0 groups with a lost ref`, no `RoutingReplayError` (DP attention and DeepEP change the MoE path; the capture must still line up);
- engine decode `gen throughput (token/s)` at 24-31 running requests against r3par-ab's 1,150-1,590 at 48.

## Result of steps 1 and 2 (2026-10-09)

Winner: **speculation 5 steps / 6 draft tokens + fp8 KV cache** (`training-runs/.../acuadron-agentic-debt-engine-ab-v3`): at the same
load the engines decode +47% (2,325 vs 1,579 tok/s median), accept 3.09 vs 2.68, KV usage 0.29 vs 0.52; rollout 0 -40% wall time;
log-prob gap 0.022 / 0.024 (below r3par-ab's 0.033 / 0.036), 0 lost refs. The bench table is in `README.md` (2026-10-08 section).
Keys for `miles-config` (edit in place, they exist): `sglang_speculative_num_steps: 5`, `sglang_speculative_num_draft_tokens: 6`,
`sglang_kv_cache_dtype: fp8_e4m3`. Not taken: DP attention (slower, numerics off), deepep (no bf16 MoE runner), fp8 weights
(needs a modelopt_fp8 checkpoint), top-k 2 drafts (DSA backend refuses at page size 64).

## Step 3 — launch final-v10

`training-runs/harbor-rl-glm53-flash/acuadron-agentic-debt-final-v10/workflow-512.yaml` is the production workflow (batch 512, 16 + 48 nodes, r24, token-level loss, no std normalisation, `NatsRolloutFn` + `max_weight_staleness 16`, `arena_inflight_multiplier 8`, 576 gyms); its engine arms are commented at the end of `miles-config`. Fill in the winner (same editing rule as step 2), then:

```bash
kubectl --context arena-prod-bom-v2 -n arena-tasks create -f training-runs/harbor-rl-glm53-flash/acuadron-agentic-debt-final-v10/workflow-512.yaml --dry-run=server -o name
argo --context arena-prod-bom-v2 -n arena-tasks stop acuadron-agentic-debt-final-v9-dx8b7   # frees its 64 nodes; v10 needs 64
kubectl --context arena-prod-bom-v2 -n arena-tasks create -f training-runs/harbor-rl-glm53-flash/acuadron-agentic-debt-final-v10/workflow-512.yaml
```

`workflow-256.yaml` is the batch-256 variant (16 + 64 nodes, multiplier 12, 432 gyms, ~9-10 min steps) if the engines do not reach 2x.

After launch: step 0 ends about 55 min after submit; `materialized expert blobs for 64 groups` under 300 s; `rollout/queue_depth_at_start` should stay above 0 but not grow without bound (growing = raise nothing, the trainer is the limit; zero = raise `arena_inflight_multiplier` and `gym-replicas` together, 1.125 gyms per group in flight); `rollout/num_old_age_dropped` under ~6 per step; `rollout/total_lengths` flat around 30k after step 8.

## Do not

- Launch production with an arm that failed the step-2 gap or capture check.
- Raise `arena_inflight_multiplier` without `gym-replicas`, or past what the mount takes (routing blobs are 1,440 B per token; v9 wrote about 0.7 TB/h).
- Set `arena_skip_prompt_above_reward` on this run without a decision: it never revisits a prompt once its last mean reward passes the threshold.
